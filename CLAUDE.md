## Project at a Glance

**What it does:** Git-like version control for AI prompts and their LLM responses.  
**Stack:** TypeScript (strict) · React 18 · Node.js · Express · Drizzle ORM · PostgreSQL 15  
**Monorepo layout:** npm workspaces — `src/api` (backend), `src/frontend` (React SPA), `src/shared` (shared types)

  pages/         # One component per route — thin, delegates to hooks

    api.ts       # Typed API client (fetch wrapper) — single file, all endpoints

## Non-Obvious Conventions

### Versioning
- Version numbers are **1-indexed** integers, not UUIDs. The UUID in `prompt_versions.id` is the stable foreign key; `version_number` is for display only.
- Rollback **always creates a new version** — it never mutates history. A rollback of v3 to v1 creates v4 with v1's content and sets `parent_version_id` to v1's UUID.
- The `content` column stores the **raw prompt text** — no encoding, no compression. This keeps diffing straightforward.

### Diff Service
- The diff service (`src/api/services/diff.service.ts`) is a pure function with no DB dependency — easy to unit test in isolation.
- Default diff mode is **word-level**. Character-level is available but verbose for long prompts.

### Auth
- Access tokens expire in **15 minutes**. Refresh tokens expire in **7 days** and are stored in an `httpOnly` cookie (not localStorage).
- The `project_members` table controls access. A user who owns a project is inserted into `project_members` with role `owner` automatically on project creation — do not bypass this.

### Database
- Use `gen_random_uuid()` for IDs (PostgreSQL built-in) — not `uuid_generate_v4()` (requires extension).
- Drizzle schema is in `src/api/db/schema.ts`. **One file only** — do not split schema across files.
- All queries must go through typed query functions in `src/api/db/queries/` — no raw SQL strings in route handlers or services.

### Frontend
- All API calls go through `src/frontend/lib/api.ts`. Never call `fetch` directly in components or hooks.
- React Query (`@tanstack/react-query`) manages server state. No `useState` + `useEffect` for async data.
- The diff view uses a custom renderer, not a third-party diff library — see `src/frontend/components/DiffView.tsx`.

## Environment Variables

See `.env.example` for all required vars. Key ones:

| Variable | Purpose |
|----------|---------|
| `DATABASE_URL` | PostgreSQL connection string |
| `JWT_SECRET` | HMAC secret for access tokens (min 32 chars) |

| `PORT` | API server port (default: 3001) |

| `FRONTEND_URL` | CORS origin whitelist for the API |

## Common Pitfalls

- **Do not** run `npm run db:migrate` against the development DB while integration tests are running — tests use a separate `TEST_DATABASE_URL`.
- **Do not** import from `src/api` in `src/frontend` or vice versa — only import from `src/shared`.
- **Do not** use `console.log` in production code — use the structured logger (`src/api/lib/logger.ts`).
- Drizzle's `.returning()` on batch inserts requires PostgreSQL ≥ 15. Local dev should match CI (PostgreSQL 15).
